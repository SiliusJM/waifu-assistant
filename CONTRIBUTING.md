# Contribuir

## Flujo

1. Leer AGENTS.md, docs/PROJECT_STATUS.md y la documentación de la fase actual.
2. Revisar git status y entender cualquier cambio pendiente.
3. Mantener el cambio dentro de la fase activa.
4. Documentar una decisión arquitectónica importante en un ADR.
5. Ejecutar npm run build, npm run lint y npm test.
6. Revisar git diff y describir riesgos o trabajo pendiente.
7. Crear un commit pequeño con un mensaje claro.

## Dependencias

Antes de añadir una dependencia, comprobar necesidad, mantenimiento, licencia, compatibilidad, tamaño e impacto de seguridad. No fijar una tecnología candidata solo por comodidad.

## Cambios de fase

Una fase requiere criterios de aceptación verificables, documentación actualizada, pruebas disponibles ejecutadas y un checkpoint Git. No se implementan funcionalidades de fases posteriores como preparación prematura.
